# Data dictionary

All tables live in `pipeline/data/processed/` as Parquet (typed) and CSV (UTF-8,
lists joined with `; `). They are regenerated by `python -m prism_pipeline.cli`.

## Provenance classes

Every field belongs to exactly one class. The UI shows this as a badge.

| Class | Meaning | UI badge |
|---|---|---|
| **OFFICIAL** | Printed in a PAIMANA Flash Report, transcribed as-is | OFFICIAL |
| **DERIVED** | Computed deterministically from official fields (formula documented here) | DERIVED |
| **NORMALISED** | Official value mapped to a canonical form (mapping is auditable) | OFFICIAL (normalised) |
| **PIPELINE** | Bookkeeping added by the pipeline (provenance, flags) | — |

Model outputs (risk scores, forecasts) are added in Phase 2 as a separate class, **MODEL ESTIMATE**.

Conventions:
- Money is in **₹ crore**.
- Dates are month-precision and stored as the first day of the month (reports print `MM/YYYY`).
- `None`/empty means **not reported**. The pipeline never imputes values.

## `projects` — one row per project in the latest report (Aug 2026, 1,731 rows)

The master table the web app is built on. It includes all `ongoing_long` fields (below) for the latest month, plus:

| Field | Class | Definition |
|---|---|---|
| `revised_cost_latest_cr` | DERIVED | Most recent **non-zero** revised cost reported for this project in any month ≤ latest. Needed because the Aug 2026 report prints 0.00 for every revised cost. |
| `revised_cost_asof` | PIPELINE | Report month `revised_cost_latest_cr` came from (currently `2026-07` for all 1,694 projects that have one). |
| `legacy_ocms_code`, `pmg_id` | OFFICIAL | Carried forward from the most recent month that printed them (Apr/May 2026). |
| `first_seen_month` | DERIVED | First report month (of those ingested) in which the project appears. |
| `months_observed` | DERIVED | Number of ingested reports listing the project as ongoing (1–5). |
| `newly_added_month` | OFFICIAL | Month the project appeared in Table 4 "Newly Added Projects", if any. |
| `dq_flags` | PIPELINE | Data-quality rule IDs raised for this project in the latest month (see `data-quality-report.md`). |
| `dq_has_error` | PIPELINE | True if any flag has severity `error`; such rows are excluded from model training. |

## `ongoing_long` — one row per (report month, project) from Table 6 (9,321 rows)

| Field | Class | Definition / source |
|---|---|---|
| `source_month` | PIPELINE | Report month `YYYY-MM` |
| `source_table`, `source_page` | PIPELINE | `Table 6` and the 1-based PDF page, so any row can be checked by hand |
| `sl_no` | OFFICIAL | Serial number in Table 6 |
| `project_code` | OFFICIAL | PAIMANA project code, the join key across months (never missing; unique per month) |
| `project_name` | OFFICIAL | Project name (black text in the Name cell) |
| `agency_raw` | OFFICIAL | Implementing agency exactly as printed (maroon text) |
| `agency_key` | NORMALISED | Canonical agency key, e.g. `NCL` for both "Northern Coalfields Limited [NCL]" and "NCL - CIL" |
| `agency` | NORMALISED | Display name, preferring "Full Name [ACRONYM]" |
| `agency_parent` | NORMALISED | Parent group where printed, e.g. `CIL` for "NCL - CIL" |
| `legacy_ocms_code` | OFFICIAL | Legacy OCMS code (Apr/May only) |
| `pmg_id` | OFFICIAL | PMG ID (Apr/May only) |
| `name_parse_method` | PIPELINE | `color` (split using the report's span colours) or `regex` (fallback). All 9,321 rows used `color`. |
| `ministry` | OFFICIAL | Line ministry/department (Table 6 group heading) |
| `ministry_short` | NORMALISED | Short label (MoRTH, MoR, DoT, …); follows PAIMANA's own abbreviations |
| `sector` | OFFICIAL | Sector (Table 6 sub-heading) |
| `hml_category` | OFFICIAL | Harmonized Master List 2022 category, from the report's HML sector-overview pages |
| `state_label` | OFFICIAL | State/UT, or `Multi-States`, `PAN India`, `Offshore` |
| `states` | OFFICIAL | List of states (the members of a Multi-States project; empty for PAN India/Offshore) |
| `is_ner_official` | OFFICIAL | Listed in Table 5 "Ongoing Projects of North-East Region" |
| `is_ner_by_state` | DERIVED | Any state in the 8 NE states |
| `date_of_approval` | OFFICIAL | Date of approval (None when printed `NA`) |
| `start_date` | OFFICIAL | Start date |
| `original_doc` | OFFICIAL | Original / target date of completion |
| `revised_doc` | OFFICIAL | Revised date of completion (None when printed `(-)`) |
| `original_cost_cr` | OFFICIAL | Original sanctioned cost |
| `revised_cost_cr` | OFFICIAL | Latest revised cost as printed; **None when printed 0.00** |
| `revised_cost_printed_zero` | PIPELINE | True if the report printed 0.00 (all of Aug 2026) |
| `cumulative_expenditure_cr` | OFFICIAL | Cumulative expenditure to date |
| `physical_progress_pct` | OFFICIAL | Physical progress, 0–100 |
| `cost_category` | DERIVED | `Mega` if original cost ≥ ₹1,000 Cr, else `Major` (definition printed on report page 4) |

## `completed` — Table 3 "Completed Projects During Month" (227 rows)

The same identity fields as `ongoing_long`, plus:

| Field | Class | Definition |
|---|---|---|
| `actual_completion` | OFFICIAL | Actual date of completion — **the outcome label for backtesting** |
| `original_doc`, `revised_doc` | OFFICIAL | Original/target and revised DoC at completion |
| `original_cost_cr`, `revised_cost_cr` | OFFICIAL | Original and revised cost (revised None when not reported) |
| `cumulative_expenditure_cr` | OFFICIAL | Expenditure as last reported. The report notes this "may not be the actual completion cost". |

## `newly_added` — Table 4 "Newly Added Projects" (180 rows)

Identity fields, `date_of_approval`, `start_date`, `original_doc`, `revised_doc`, `original_cost_cr`, `revised_cost_cr` (all OFFICIAL).

## `lifecycle` — event log (2,771 rows)

| Field | Class | Definition |
|---|---|---|
| `project_code` | OFFICIAL | |
| `event` | DERIVED | `first_observed`, `newly_added`, `completed`, `exited`, `withheld_by_mospi` |
| `month` | OFFICIAL | Report month of the event |
| `reason`, `reason_text` | DERIVED | For exits: `completed_reported_later`, `withheld_data_inconsistency` (IDs named in the report's note), `temporarily_absent`, `railways_irpsm_onboarding` (per the report's IRPSM note), `unexplained` |

## Aggregates (all OFFICIAL)

| Table | Content |
|---|---|
| `kpis` | Overview page per month: ongoing projects, line ministries, commissioned during month, newly added, original/revised cost, expenditure (and % of revised), Mega/Major counts and cost, and the same set for the NER page (`ner_*`) |
| `ministry_totals` | Table 1: ministry × sector, ministry totals, grand total |
| `sector_overview` | HML "Sector - Overview" tables: count, original, **revised**, expenditure per sector (revised is present even in Aug 2026) |
| `group_totals` | Every "Total (n)" subtotal row in Tables 3, 4, 6 (used for reconciliation) |
| `report_notes` | Verbatim footnotes of each report |

## Pipeline tables

| Table | Content |
|---|---|
| `agency_aliases` | Every raw agency string → `key`, `display`, `parent` (audit trail for normalisation) |
| `data_quality_register` | One row per finding: rule, severity, detail, report month, table, page, project |
| `data_quality_systemic` | Report-wide patterns per month (revised cost printed zero, legacy codes present, …) |
| `reconciliation` | 855 checks: expected (official), actual (extracted), delta, pass/fail |
| `extraction_issues` | Rows that did not fit any expected shape (currently empty) |
| `manifest.json` | Pipeline version, timestamp, source PDFs with SHA-256, row counts, check and DQ summary |
